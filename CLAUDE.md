# Bodilgodkendt — Danish study hub

A single-page study tool for Chris's Danish course: **Danish to Go 3**, all six
chapters, cross-referenced with his **Studieskolen modul 3.3** class notes.

Published in two places, from the same source:

- **Website** — https://thenomadcode.github.io/bodilgodkendt/ (GitHub Pages, deployed by CI)
- **Claude Artifact** — https://claude.ai/code/artifact/5bcabe74-e2ff-4b2e-bf70-6e3e96b237cb

## Build

```bash
python3 build.py
```

No dependencies, standard library only. Writes:

- `dist/site/` — the website. The whole folder is what Pages serves;
  `dist/site/index.html` is also the file to open locally.
- `dist/index.html` — body-only, for republishing as an Artifact. **Not** a
  valid standalone document; it has no `<head>`.

To preview: `python3 -m http.server -d dist/site`.
Open it over http rather than `file://` — `localStorage` is blocked on `file://`
in Chrome, and the progress tracking silently does nothing.

## Deploying

Pushing to `main` deploys. `.github/workflows/pages.yml` runs `build.py` and
publishes `dist/site/`, so `dist/` stays untracked — never commit build output.

`assets/` holds the app icons. They are generated once, not on every build:

```bash
for s in 32 180 192 512; do rsvg-convert -w $s -h $s assets/icon-square.svg -o assets/icon-$s.png; done
```

`icon-square.svg` is full-bleed (iOS applies its own corner mask); `icon.svg`
is the rounded one browsers show in a tab. Regenerate and commit the PNGs only
if the mark changes — CI has no rasteriser.

`source/` is gitignored. The repo is public and nothing in it is ours to
redistribute; keep it local. It holds:

- `danish-to-go-3.pdf` — the textbook, rebuilt from the publuu flip-book page
  images with an invisible OCR text layer (macOS Vision, da-DK). Page index =
  printed page number.
- `danish-to-go-3.txt` — the same OCR text, one `===== Side N =====` block per
  printed page. This is what to grep. OCR slips on diacritics (`ă` for `å`,
  `œ` for `æ`); check the page image before trusting an odd form.
- `Grammatik-modul-3.3.pdf` — the class notes (chapter 1–2 material only).
- `verbs.pdf` — the verb sheet.
- `studieskolen/da/level3/` — a text dump of the Studieskolen online platform
  (login-only): `kapitelN/lektionM/opgaver/*.txt` exercise prompts,
  `kapitelN/lektionM/udtale.txt`, and `resurser/` grammar and vocabulary pages
  plus `resurser/udskrift/` listening transcripts. Reference only — never copy
  exercises wholesale into `src/`, which publishes.
- `modultest/` — the official DU3 modul 3 test material from
  danskogproever.dk (information sheets and the `33-eksempel-*` samples for
  reading, writing and both oral tasks), plus a real February 2026 written test
  from modultest.dk (Gyldendal). This is what defines the formats in the
  Modultest tab. Format reference only: every text in `src/modultest.js` is
  written for this page, and none of these may be copied in.

## Layout

```
src/hub.html      markup, CSS and all page logic. Contains a /*DATA*/ marker
                  that build.py replaces with the concatenated data modules.
src/words1.js     chapter 1 vocabulary   -> WORDS, TIERS, CATS
src/words2.js     chapter 2 vocabulary   -> WORDS_CH2
src/words3–6.js   chapters 3–6           -> WORDS_CH3 … WORDS_CH6
src/rules.js      grammar                -> RULE_GROUPS, RULES
src/verbs.js      conjugations           -> VERBS
src/listen.js     oral exam prompts      -> ORAL
src/practice.js   drills + writing tasks -> SETS, WRITING
src/modultest.js  the test's own formats -> READ_T, WRITE_T, ORAL_T
assets/           app icons — committed, regenerated by hand (see Deploying)
audio/            recorded Danish speech + manifest.json — committed, made by tools/ (see Speech)
tools/            voices.js (what to record, which voice) and tts.py (records it)
source/           textbook PDF + OCR text, class notes, verb sheet, platform dump — gitignored
dist/             build output — untracked, do not edit by hand
```

The page has seven tabs: Status, Modultest, Grammatik, Verber, Ord, Lyt & tal,
Øv dig — plus three full-screen overlays: the trainer (`#tr`), the Modultest
player (`#mt`) and the tour (`#intro`). The phone nav wraps to two rows at 360px and is now at
capacity; see the `@media (max-width:620px)` block. A new feature goes into an
existing tab or an overlay, not an eighth tab.

A global progress bar sits in the sticky nav under the tab row, next to a
theme switch that cycles Auto → Lys → Mørk. Each tab except Status and
Modultest carries its own progress bar; Status has the hero percentage instead,
and Modultest has scores and a verdict — it is not a checklist, so it gets no
bar and no tab badge.

**Chapter scope.** Status opens with "Dine kapitler": chips for each chapter
that has words. Everything with a `ch` is shown and counted only while one of
its chapters is chosen; anything without `ch` is core and always counts. The
scope is saved as `scope` inside `dtg3-hub-v1`. All rendering and every count
read the scoped arrays in `SC` (built by `computeScope()`), never `RULES`,
`VERBS`, `ALL_WORDS`, `ORAL`, `SETS` or `WRITING` directly — keep it that way.
Pruning stale ticks must run against the *full* arrays, or narrowing the scope
would delete marks.

**Dagens ord.** A spaced-repetition review at the top of the Ord tab, over the
scoped words (tier 1–2 by default). Each word has an interval in days; Igen /
Svært / Godt / Let shrink or stretch it SM-2 style (`srsCalc()`), Igen also
re-queues the word three cards later. New words come tier 1 first, then by
chapter, capped per day (10/20/30); words already ticked by hand are never
introduced. When a word's interval reaches `LEARNED` (7 days) it is ticked in
`S.known` — the only way the review feeds the Ord bar. Changing the scope ends a
running session. Space shows the answer, 1–4 grade it.

**Speech** is documented in its own section below. Rule examples and drill
answers carry markup, so their speaker text goes through `sayText()` first.

## Data shapes

**Word** (`words1.js` … `words6.js`)
```js
{da:"at lære", en:"to learn; to teach", c:"verb", t:1, p:4, n:"optional note"}
```
- `c` — one of `verb phrase noun adj adv time pron`
- `t` — usefulness tier 1–4 (1 = learn first, 4 = recognise only). Tiers are a
  judgement about real-world frequency, not something the book states.
- `p` — printed page in *Danish to Go 3*. These match the PDF and the paper book.
- `ch` is added at load time from the file the word is in. `da` must be unique
  across *all* word files — a duplicate shares its tick and shows twice.

**Rule** (`rules.js`)
```js
{g:"verbs", src:"both", ref:"Notes · Book p.33", title:"…",
 rule:"…", table:[["label","value"]], ex:["…"], trap:"…", star:true}
```
- `g` — must match an `id` in `RULE_GROUPS`, or the card renders nowhere.
- `src` — `both` (book **and** class notes — highest test probability),
  `notes`, or `book`. Drives the coloured tag.
- `star` — priority. Star rules also get a `★` prefix in `title` and are
  weighted double in the readiness score.
- `ch` — the chapter a **book** rule belongs to (for the scope). Class-notes
  rules have none and are always in scope.
- `ref` may cite the online platform as `Online K3·L2 opg. 8`.
- `rule`, `table` values, `ex` and `trap` all accept inline HTML. Everything
  else is escaped.

**Verb** (`verbs.js`)
```js
{i:"at lære", n:"lærer", d:"lærte", f:"har lært", m:"lær",
 e:"to learn; to teach", grp:"2", src:"book", ch:3}
```
- `i n d f m` = infinitiv, nutid, datid, førnutid, imperativ. `–` for none.
- `grp` — `1` (-ede), `2` (-te), `U` (irregular), `M` (modal).
- `src` — `sheet` (from `source/verbs.pdf`, **transcribed verbatim, do not
  "correct"**) or `book`.
- `ch` — chapter number, or `[1,2]` for the verbs added from chapters 1–2
  together. Sheet verbs have none.

**Drill set** (`practice.js`)
```js
{id:"tense", ch:3, name:"…", rule:"verbs", intro:"…",
 items:[{q:"Jeg ___ (flytte) …", a:"flyttede", w:"why"}]}
```
`w` accepts HTML. Answers with more than one right form are written as
`"der / som"` and the `w` says so. `ch` scopes the set; the original eight
sets have none (class-notes core). `WRITING` entries carry `ch` too, and
`ORAL` entries always have `ch` and `les`.

## Progress tracking — read before renaming anything

Progress lives in the viewer's browser only. Five keys:

| Key | Holds |
|---|---|
| `dtg3-k1-v1` | ticked words (`known`), plus the words-tab toggles |
| `dtg3-hub-v1` | marked rules, verbs and oral questions, drill scores, active tab, last-marked date, plus `miss` `hits` `sess` `exam` (see Trainer) and `scope` (chosen chapters) |
| `dtg3-theme-v1` | `auto`, `light` or `dark` — the theme switch only |
| `dtg3-srs-v1` | the Dagens ord schedule: `cards` keyed by `da` (`ivl`, `ease`, `reps`, `lapses`, `due`), plus `dir`, `perDay`, `tiers` and today's new-word count |
| `dtg3-test-v1` | Modultest: `best` reading score per task id (`s` best, `last`, `n`, `k` tries, `d` last date), `wlog` writing attempts per prompt id (`k`, `d`, `ok`, `n` words — practice and mock alike), `mocks` (last 20, each with the `items` and `writes` it contained), `drafts` and `checks` per writing id, `topics` (the two chosen oral topics), `maps` (mindmap keywords per topic), `oral` (`o1:`/`o2:` + id → count and date), `onlyNew` (the not-done-yet filter) |

**These are keyed by content strings, not ids:**

- words by `da`
- rules by `title`
- verbs by `i`
- oral questions by `q`
- drills by `setId + ':' + index`

So editing a word's `da`, a rule's `title`, a verb's `i`, an oral `q`, or
reordering the items inside a drill set **orphans that entry's saved
progress**. The Lyt & tal bar counts against the live `L_KEYS`, not
`P.listen.size`, and the boot block prunes ticks whose card is gone — that is
what stops a removed card pushing the bar past 100 %. Keep both if you edit
this area. Adding new entries is always safe. If you must rename, bump
the storage key and accept the reset, or write a migration in the boot block at
the bottom of `hub.html`.

The readiness percentage on the Status tab is weighted: grammar 30 % (half of
that the ★ rules), words 25 % (tier 1–2 only), drills 25 %, verbs 20 %. It is
self-reported — it counts what has been marked, not what is known. The page
says so, and it should keep saying so. Lyt & tal is tracked and gets its own
bar, but is deliberately **not** weighed into the headline; adding it means
rebalancing the other four and updating the "Sådan tælles det" copy.

Each area shows one number in three places — its page bar, its tab badge and
its Status card — and `updateBars()`, `tabBadges()` and `renderStatus()` all
read it from the same `stats()` call. The global bar is `stats().ready`, the
same number as the Status hero. If you add an area, keep those three in step,
and note that the Ord bar reports the tier 1–2 figure, not every word.
All of these are computed over the chosen chapter scope.
`syncProgress()` refreshes all three; call it after anything that mutates
`P` or `S.known`.

## Adding content

- **Words:** add to the chapter's `src/wordsN.js`. A new chapter file must also
  go into `MODULES` in `build.py` (before `rules.js`) and into the
  `ALL_WORDS` list in `hub.html`; the chapter chips, scope chips and the
  masthead range all follow from the data.
- **Rules, verbs, oral prompts, drills, writing:** append to the shared files
  and give each a `ch`. They render straight from the arrays, and the trainer
  picks up new words, verbs and drill items on its own.
- Check `da`, rule titles, verb infinitives, set ids and oral `q` for
  duplicates across every file before shipping — all of them are storage keys.

## Republishing

`dist/index.html` is the file to publish. It is deliberately **body-only** — no
doctype, `<html>`, `<head>` or `<body>` tags — because the Artifact runtime
wraps it. Publishing it needs a Claude session that has the Artifact tool, and
the existing URL must be passed explicitly or a second artifact gets created
instead of updating this one.

The Artifact build deliberately omits the favicon, manifest and `theme-color`
tags that `dist/site/index.html` carries — the Artifact runtime sets its own
favicon, and a `<link rel=manifest>` would 404 against its origin. `build.py`
injects those into the site build only, via `HEAD_EXTRA`. The theme switch
updates `theme-color` at runtime and no-ops when the meta is absent.

Republishing the Artifact and deploying the website are independent: `git push`
updates the website only.

## Modultest

The module 3 test in its own formats, from `source/modultest/`. Written part:
four reading task types in 50 minutes with no aids — `cloze` (opgave 1, ten
gaps), `chat` (2A/2B, pick the missing replies, three left over), `insert`
(opgave 3, the missing sentence in each of five paragraphs) and `match`
(opgave 4, three people, seven *Hvem …?* questions) — then a `klage` with four
set points and a `mail` reply of at least 90 words. Oral part: an emneopgave
(two prepared topics, a keyword-only mindmap, 1–2 minutes, then follow-up
questions) and a four-picture preference conversation. Both oral parts and the
whole test are judged bestået / ikke bestået.

- **Reading is marked by the page.** It is the only score on the site that is
  not self-reported, and it is deliberately kept out of `stats().ready`. The
  Status tab shows it beside the headline, never inside it, and "Sådan tælles
  det" says why. The pass bar is `PASS` (60 %): the official mark is not
  published, and the page says so wherever it gives a verdict.
- **Writing is self-ticked.** Opening, sign-off and the 90-word count are
  detected (`writeAuto()`); the content points are ticked by the learner.
- **The mock** (`startMock()`) draws one cloze, two chats, one insert and one
  match — least-practised first — under a 50-minute clock that hands reading in
  when it runs out, then one klage and one mail at 30 minutes each. It ends in
  a GODKENDT / IKKE ENDNU stamp.
- **Done / not done is tracked for everything** — every reading task, every
  writing prompt, every oral topic and picture theme shows a dot, its last
  date and its count, and each section heading says *x af N lavet*. A task done
  inside a mock counts exactly like one done on its own, and the mock rotates
  by `tries()`, so it reaches the untouched tasks first. The *Kun dem, jeg ikke
  har lavet* chip filters the lists.
- **Oral questions are spoken**, not shown, when a Danish voice exists — in the
  room you hear them. Without a voice they are shown as text.
- Data shapes are in the header of `modultest.js`. Every reading item carries
  its English `w`, which names the clue in the text. A cloze has exactly one
  defensible option per gap; a chat reply must fit the message before **and**
  after it; a match question's subject appears in more than one text but is true
  of one person. Check all three by reading every option in place before adding
  a task.

## The tour

Three short steps (`TOUR` in `hub.html`) for a first-time visitor on a phone:
what the page is, where things are, and that progress is saved on this phone
and browser only. A six-step version was too much — keep it short. It opens by
itself when neither `dtg3-hub-v1` nor `dtg3-k1-v1` exists (`FIRST_VISIT`, read
before boot's `showTab()` writes the hub key), and the `[data-tour]` links in
the masthead and footer reopen it. It stores nothing of its own. If you add a
tab or change how progress is saved, the tour's copy has to change with it.

## The trainer

Opened from `[data-train]` buttons — one per scope, on Status and in the Ord,
Verber and Øv dig toolbars. Twelve questions a round, drawn from data that is
already on the page; nothing new is authored for it.

| Type | Source | Shape |
|---|---|---|
| `da2en` | words, tier 1–2 | four-option multiple choice |
| `en2da` | words, tier 1–2 | typed |
| `listen` | words, tier 1–2 | speaks the Danish, four-option meaning |
| `blank` | the 67 `SETS` items | typed — they are already `Jeg ___ (flytte)` |
| `verb` | `VERBS` × the four forms | typed |

Scopes are `all`, `words`, `verbs`, `drills` and `miss`. Every one draws from
the chapter scope (`SC.tier12`, `SC.verbs`, `SC.sets`), and `scopedMiss()`
hides mistakes from unchosen chapters without deleting them — `rebuildMiss()`
stays unscoped because the boot prune runs on it. `planFor()` decides the
type mix; the mixed plan gives two of its twelve slots to whichever of words,
verbs or drills `stats()` says is weakest.

**It writes to the same keys the notebook does.** Question keys are content
strings, exactly like everything else: words `w:` + `da`, verbs `v:` + `i` + `:`
+ form letter, drills `setId:index` — the drill key *is* the `P.drills` key, so
answering a drill in the trainer scores that drill. Renaming a word, verb or
drill orphans its trainer history the same way it orphans a tick.

- `P.miss` — `[{t,k}]`, newest first, capped at 60. Wrong answers go on, right
  answers come off. Weighted 5× when picking questions; also rendered as the
  *Mine fejl* section on Status. Pruned at boot against the live data, the same
  way `P.listen` is.
- `P.hits` — right-answers-in-a-row per key, reset to 0 on a wrong one. **Two in
  a row ticks the word into `S.known` or the verb into `P.verbs`.** That is the
  whole reason training needs no weight of its own in the readiness score: it
  reaches the existing four numbers through the same door as marking by hand.
  If you change that rule, the "Sådan tælles det" copy has to change with it.
- `P.sess` — `[{d,n,ok}]`, last 20, for the Status card only.
- `P.exam` — a legacy exam date. The countdown now reads `TEST_DATES` in
  `modultest.js` (written 19 Nov 2026, oral 24 Nov 2026) and shows both;
  `P.exam` is only a fallback if those are removed.

`grade()` is deliberately forgiving: case, spacing and punctuation are ignored,
`ae`/`oe`/`aa` are accepted for `æøå` so a phone keyboard is never the reason an
answer is wrong, `a / b` answers take either or both, and a missing article or
`at` returns `near` — which counts as correct but says so. `en2da` also accepts
any other word carrying the same English gloss. Keep that generosity; a trainer
that fails you on typing is a trainer you stop opening.

## Speech

**Recorded first, browser voice as fallback.** Every line the page can speak
is recorded with Google Cloud Text-to-Speech, Chirp 3 HD, `da-DK`, six voices
(Kore, Aoede, Leda; Charon, Puck, Orus):

```bash
node tools/voices.js > audio/manifest.json   # every speakable line + its voice
python3 tools/tts.py                         # records only what is missing
python3 build.py
```

- `tools/voices.js` mirrors every `sayBtn()` / `speak()` call site — words,
  verbs, rule examples, drill answers, oral prompts and phrases, Modultest
  topics, picture intros and examiner questions. **Add a new kind of spoken
  text to the page and you must add it there too**, or it plays in the browser
  voice. Voices are picked by context: an examiner voice per topic
  (alternating man / woman), *min kone* → a man, *min mand* → a woman,
  otherwise spread over all six by hash, so a line always keeps its voice.
- Files are `audio/<key>.mp3`, where key is FNV-1a of the whitespace-normalised
  text in base 36. `sayKey()` in `hub.html` computes the same key — keep the
  two functions identical. Editing a word's `da` or an example's text simply
  makes a new key; re-run both tools, and the old file is reported as stale.
- `audio/` is committed, like the icons: CI has no key and does not record.
  The key lives in `source/google-text-to-speach-api-key.txt` (gitignored) or
  `GOOGLE_TTS_KEY`, on the Google Cloud project `bodilgodkendt`. Never put it
  anywhere that publishes.
- `build.py` copies the clips to `dist/site/audio/` and writes their keys into
  `AUDIO_KEYS` for the website. The Artifact gets an empty list (it cannot carry
  two thousand files) and uses the browser voice throughout.
- **Langsomt** (`#slowBtn`, saved as `slow` in `dtg3-hub-v1`) plays recordings
  at 0.75× with pitch preserved, and the browser voice at 0.7.

The fallback is browser `speechSynthesis`. `findVoice()` looks for a Danish
voice at boot and again on `voiceschanged` (Chrome loads them asynchronously)
and toggles `body.has-tts`. A recorded line's button carries `.rec` and shows
at once; any other `.say` stays hidden until `has-tts`. `canSpeak()` decides
whether the `listen` question type and spoken oral questions are offered — a
device with neither recordings nor a Danish voice shows no audio controls at
all rather than dead ones, the same call as commit `f475bfb`.

One delegated `click` listener on `document`, **capture phase**, handles every
speaker button. Capture is what stops the click also reaching the row
underneath and revealing a word or a verb form.

## House rules

- **Danish for headings and labels, English for anything that explains.** The
  tab names, section headings, the one-word verdicts and the grammatical terms
  (`datid`, `førnutid`) are Danish, because they are the material. Every
  instruction, hint, button and piece of feedback prose is English. The point of
  the page is to teach Danish, not to be in Danish.
- Danish content is checked before it ships. Every form in `verbs.js` marked
  `src:"sheet"` was diffed against `source/verbs.pdf` programmatically; the
  rest was reviewed against Retskrivningsordbogen. Keep that bar.
- Examples come from the book or the class notes wherever possible, not
  invented. Where a drill mirrors a book exercise, the `w` note says which page
  and where the book's own answer key is.
- Both colour themes are token-driven in `:root`, `@media (prefers-color-scheme: dark)`
  guarded with `:root:not([data-theme="light"])`, and `:root[data-theme="dark"]`.
  Never declare a colour only inside a media or `[data-theme]` block.
- `.bar` is the toolbar class, `.pbar` is the per-page progress bar and
  `.gprog`/`.gbar` is the global one in the nav. `.bar` and `.pbar` collided
  once; don't reintroduce that.
- The theme is applied by a small inline script directly after `</style>`,
  before the page paints, so a saved choice never flashes the wrong palette.
  `data-theme` is removed entirely for `auto` so the media query takes over.
