# Prøveklar — Danish study hub

A single-page study tool for Chris's Danish course: **Danish to Go 3**, chapters 1–2,
cross-referenced with his **Studieskolen modul 3.3** class notes.

Published in two places, from the same source:

- **Website** — https://thenomadcode.github.io/proveklar/ (GitHub Pages, deployed by CI)
- **Claude Artifact** — https://claude.ai/code/artifact/5bcabe74-e2ff-4b2e-bf70-6e3e96b237cb

## Build

```bash
python3 build.py
```

No dependencies, standard library only. Writes:

- `dist/site/` — the website. The whole folder is what Pages serves;
  `dist/site/index.html` is also the file to open locally.
- `dist/index.html` — body-only, for republishing as an Artifact. **Not** a
  valid standalone document; it has no `<head>`.

To preview: `python3 -m http.server -d dist/site`.
Open it over http rather than `file://` — `localStorage` is blocked on `file://`
in Chrome, and the progress tracking silently does nothing.

## Deploying

Pushing to `main` deploys. `.github/workflows/pages.yml` runs `build.py` and
publishes `dist/site/`, so `dist/` stays untracked — never commit build output.

`assets/` holds the app icons. They are generated once, not on every build:

```bash
for s in 32 180 192 512; do rsvg-convert -w $s -h $s assets/icon-square.svg -o assets/icon-$s.png; done
```

`icon-square.svg` is full-bleed (iOS applies its own corner mask); `icon.svg`
is the rounded one browsers show in a tab. Regenerate and commit the PNGs only
if the mark changes — CI has no rasteriser.

`source/` (the textbook and class PDFs) is gitignored. The repo is public and
those are not ours to redistribute; keep them local.

## Layout

```
src/hub.html      markup, CSS and all page logic. Contains a /*DATA*/ marker
                  that build.py replaces with the concatenated data modules.
src/words1.js     chapter 1 vocabulary   -> WORDS, TIERS, CATS
src/words2.js     chapter 2 vocabulary   -> WORDS_CH2
src/rules.js      grammar                -> RULE_GROUPS, RULES
src/verbs.js      conjugations           -> VERBS
src/listen.js     oral exam prompts      -> ORAL
src/practice.js   drills + writing tasks -> SETS, WRITING
assets/           app icons — committed, regenerated by hand (see Deploying)
source/           the two PDFs this was built from — gitignored, local only
dist/             build output — untracked, do not edit by hand
```

The page has six tabs: Status, Grammatik, Verber, Ord, Lyt & tal, Øv dig.

A global progress bar sits in the sticky nav under the tab row, next to a
theme switch that cycles Auto → Lys → Mørk. Each tab except Status carries its
own progress bar; Status has the hero percentage instead.

## Data shapes

**Word** (`words1.js`, `words2.js`)
```js
{da:"at lære", en:"to learn; to teach", c:"verb", t:1, p:4, n:"optional note"}
```
- `c` — one of `verb phrase noun adj adv time pron`
- `t` — usefulness tier 1–4 (1 = learn first, 4 = recognise only). Tiers are a
  judgement about real-world frequency, not something the book states.
- `p` — printed page in *Danish to Go 3*. These match the PDF and the paper book.

**Rule** (`rules.js`)
```js
{g:"verbs", src:"both", ref:"Notes · Book p.33", title:"…",
 rule:"…", table:[["label","value"]], ex:["…"], trap:"…", star:true}
```
- `g` — must match an `id` in `RULE_GROUPS`, or the card renders nowhere.
- `src` — `both` (book **and** class notes — highest test probability),
  `notes`, or `book`. Drives the coloured tag.
- `star` — priority. Star rules also get a `★` prefix in `title` and are
  weighted double in the readiness score.
- `rule`, `table` values, `ex` and `trap` all accept inline HTML. Everything
  else is escaped.

**Verb** (`verbs.js`)
```js
{i:"at lære", n:"lærer", d:"lærte", f:"har lært", m:"lær",
 e:"to learn; to teach", grp:"2", src:"book"}
```
- `i n d f m` = infinitiv, nutid, datid, førnutid, imperativ. `–` for none.
- `grp` — `1` (-ede), `2` (-te), `U` (irregular), `M` (modal).
- `src` — `sheet` (from `source/verbs.pdf`, **transcribed verbatim, do not
  "correct"**) or `book`.

**Drill set** (`practice.js`)
```js
{id:"tense", name:"…", rule:"verbs", intro:"…",
 items:[{q:"Jeg ___ (flytte) …", a:"flyttede", w:"why"}]}
```
`w` accepts HTML. Answers with more than one right form are written as
`"der / som"` and the `w` says so.

## Progress tracking — read before renaming anything

Progress lives in the viewer's browser only. Three keys:

| Key | Holds |
|---|---|
| `dtg3-k1-v1` | ticked words (`known`), plus the words-tab toggles |
| `dtg3-hub-v1` | marked rules, verbs and oral questions, drill scores, active tab, last-marked date |
| `dtg3-theme-v1` | `auto`, `light` or `dark` — the theme switch only |

**These are keyed by content strings, not ids:**

- words by `da`
- rules by `title`
- verbs by `i`
- oral questions by `q`
- drills by `setId + ':' + index`

So editing a word's `da`, a rule's `title`, a verb's `i`, an oral `q`, or
reordering the items inside a drill set **orphans that entry's saved
progress**. The Lyt & tal bar counts against the live `L_KEYS`, not
`P.listen.size`, and the boot block prunes ticks whose card is gone — that is
what stops a removed card pushing the bar past 100 %. Keep both if you edit
this area. Adding new entries is always safe. If you must rename, bump
the storage key and accept the reset, or write a migration in the boot block at
the bottom of `hub.html`.

The readiness percentage on the Status tab is weighted: grammar 30 % (half of
that the ★ rules), words 25 % (tier 1–2 only), drills 25 %, verbs 20 %. It is
self-reported — it counts what has been marked, not what is known. The page
says so, and it should keep saying so. Lyt & tal is tracked and gets its own
bar, but is deliberately **not** weighed into the headline; adding it means
rebalancing the other four and updating the "Sådan tælles det" copy.

Each area shows one number in three places — its page bar, its tab badge and
its Status card — and `updateBars()`, `tabBadges()` and `renderStatus()` all
read it from the same `stats()` call. The global bar is `stats().ready`, the
same number as the Status hero. If you add an area, keep those three in step,
and note that the Ord bar reports the tier 1–2 figure, not all 385 words.
`syncProgress()` refreshes all three; call it after anything that mutates
`P` or `S.known`.

## Adding chapter 3

1. Add `src/words3.js` exporting `WORDS_CH3`, same shape and same four tiers.
2. Add it to `MODULES` in `build.py` and to the merge line in `hub.html`
   (`const ALL_WORDS = …`).
3. Add a `ch3` chip to `wFilters` in `hub.html`.
4. Append to `RULES`, `VERBS`, `ORAL`, `SETS` as needed — those
   render straight from the arrays and need no other change.
5. Update the masthead eyebrow (`Kapitel 1–2`) and the lede.

## Republishing

`dist/index.html` is the file to publish. It is deliberately **body-only** — no
doctype, `<html>`, `<head>` or `<body>` tags — because the Artifact runtime
wraps it. Publishing it needs a Claude session that has the Artifact tool, and
the existing URL must be passed explicitly or a second artifact gets created
instead of updating this one.

The Artifact build deliberately omits the favicon, manifest and `theme-color`
tags that `dist/site/index.html` carries — the Artifact runtime sets its own
favicon, and a `<link rel=manifest>` would 404 against its origin. `build.py`
injects those into the site build only, via `HEAD_EXTRA`. The theme switch
updates `theme-color` at runtime and no-ops when the meta is absent.

Republishing the Artifact and deploying the website are independent: `git push`
updates the website only.

## House rules

- Danish content is checked before it ships. Every form in `verbs.js` marked
  `src:"sheet"` was diffed against `source/verbs.pdf` programmatically; the
  rest was reviewed against Retskrivningsordbogen. Keep that bar.
- Examples come from the book or the class notes wherever possible, not
  invented. Where a drill mirrors a book exercise, the `w` note says which page
  and where the book's own answer key is.
- Both colour themes are token-driven in `:root`, `@media (prefers-color-scheme: dark)`
  guarded with `:root:not([data-theme="light"])`, and `:root[data-theme="dark"]`.
  Never declare a colour only inside a media or `[data-theme]` block.
- `.bar` is the toolbar class, `.pbar` is the per-page progress bar and
  `.gprog`/`.gbar` is the global one in the nav. `.bar` and `.pbar` collided
  once; don't reintroduce that.
- The theme is applied by a small inline script directly after `</style>`,
  before the page paints, so a saved choice never flashes the wrong palette.
  `data-theme` is removed entirely for `auto` so the media query takes over.
